    Integração via API REST

    Todos os endpoints abaixo são assíncronos: você inicia um job com POST /api/migrate, acompanha com SSE ou polling, e obtém o JSON quando status for done. Documentação interativa em /docs (OpenAPI).

    • Base URL desta instância: —
    • Autenticação: desativada (defina API_KEY no .env para exigir header).
    • Header quando autenticação ativa: X-Api-Key: sua-chave
    • Timeout padrão do scraping: configurável via SCRAPE_TIMEOUT_S no servidor
    POST /api/migrate

    Inicia extração. Resposta 202 com job_id, URLs de status, eventos SSE e cancelamento.

    curl -X POST "$BASE/api/migrate" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.ifood.com.br/delivery/..."}'
    GET /api/migrate/{job_id}

    Polling do job: status, progress, result (quando concluído) ou error.

    curl "$BASE/api/migrate/JOB_ID"
    SSE /api/migrate/{job_id}/events

    Stream em tempo real. Eventos: progress, done, error, cancelled. A interface web usa EventSource neste endpoint.

    # JavaScript (navegador)
const es = new EventSource("$BASE/api/migrate/JOB_ID/events");
es.addEventListener("progress", (e) => console.log(JSON.parse(e.data)));
es.addEventListener("done", (e) => console.log(JSON.parse(e.data)));
    POST /api/migrate/{job_id}/cancel

    Cancela job em pending ou running.

    curl -X POST "$BASE/api/migrate/JOB_ID/cancel"
    GET /api/scrapes

    Lista histórico. Query: limit, offset, status (pending, running, done, error, cancelled).

    curl "$BASE/api/scrapes?limit=20&status=done"
    GET /api/scrapes/{job_id}

    Detalhe de um scraping (mesmo formato do polling de migrate).

    curl "$BASE/api/scrapes/JOB_ID"
    DELETE /api/scrapes/{job_id}

    Remove do histórico. Se ainda estiver ativo, cancela antes de apagar.

    curl -X DELETE "$BASE/api/scrapes/JOB_ID"
    GET /api/health

    Health check público (sem API key). Retorna estratégia, jobs ativos e estatísticas.

    curl "$BASE/api/health"
    Fluxo recomendado (polling)
    1. POST /api/migrate com a URL da loja → guarde job_id
    2. Em loop: GET /api/migrate/{job_id} a cada 2–5 s até status terminal
    3. Se done, use o campo result como JSON do cardápio
    4. Para UX em tempo real, prefira SSE em events_url em vez de polling agressivo

    Expondo via ngrok: defina API_KEY no .env e envie X-Api-Key em todas as rotas protegidas (exceto /api/health e SSE de eventos).
